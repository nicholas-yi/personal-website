field note / Nicholas Yi

What makes an evaluation trustworthy?

On the distance between a reassuring number and a result worth trusting.

A better score is reassuring. I do not think that reassurance is necessarily misplaced; a comparison can tell us something real. I just want to know which comparison we actually made.

Was the answer wrong, or did the run never reach an answer? It is a small distinction until both attempts become the same cell in a table. Then the distinction is most of what I need to understand.

What actually happened?

If a run produces an incorrect answer, it has failed the task. If ingestion times out before retrieval, there may be no answer to evaluate. A judge can also fail to return a usable grade. Each attempt leaves us without the result we wanted, but the missing result does not tell us the same thing.

A completed-run accuracy score can still be useful. It asks how often the system was right among the attempts we could grade. The complication is that a system can answer those questions well and frequently fail before it gets that far.

I want both numbers. How well did it answer, and how often did it reach an answer at all?

Keeping that distinction does not mean making the inconvenient attempts disappear. An unfinished run belongs in the record, with its failure stage and missing grade intact. Otherwise, the table can become more reassuring precisely because we have removed the part that made the experiment difficult.

That is why I care about isolation, stage-level telemetry, and recoverable runs. They help keep the evidence behind a comparison visible. A retry can be sensible (sometimes the infrastructure really did interrupt the work), but it should not quietly replace the attempt that came before it. The inputs, configuration, and what was held fixed matter too. If the system and the setup both changed, another run cannot tell us which change deserved the credit.

What did the test ask?

Memory makes the boundary of a test particularly tangible. An agent might recall the time of a meeting correctly, then keep returning that time after the plan changes. A deleted source might still lend its words to a searchable summary. The earlier answer was correct. The state behind the later answer was not.

Stashbird's public evaluation separates question answering from its update and deletion studies because the ability to answer does not establish that the underlying state has been revised correctly. The controlled lifecycle studies hold semantic decisions fixed. That lets them test reconciliation without confusing it with the separate question of whether the model interpreted the conversation correctly.

I would rather have a result that answers a smaller question honestly than one that seems to settle everything. Not because I want less confidence in the work, but because I want the confidence to have somewhere solid to stand. A good score can be the beginning of that understanding. It should not have to be the end.
